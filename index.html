PAUSE & THINK

How would you share the secret key safely?

Sending the key beside the encrypted message defeats the purpose. Symmetric encryption is fast, but both people need a secure way to obtain the shared key.

Try this in class

  1. Encrypt the same message twice. Compare the results.
  2. Try decrypting with the wrong key.
  3. Change the encrypted message. Can it still be opened?

Randomness makes each encryption different. A failed decryption does not reveal the original message.

How do these methods compare?
SymmetricAsymmetric
KeysOne shared secretA public/private pair
Encrypt withShared keyRecipient’s public key
Decrypt withSame shared keyRecipient’s private key
In this labAES-GCM, 256 bitsRSA-OAEP, 2048 bits, SHA-256
Typical roleEncrypting message dataProtecting small secrets such as session keys

Real systems often combine both methods: asymmetric cryptography establishes or protects a symmetric session key. Encryption provides confidentiality; it does not by itself prove who sent a message. Base64 is a display encoding, not encryption.
